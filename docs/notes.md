# 学習ノート

課題を進めながら理解したことを、自分の言葉で残す。レポートの「手法」の素材にする。

## 1. Genesis の基本（2026-10-31, `src/hello_go2.py`）

Genesis のプログラムはいつも次の順番で書く。

| 手順 | コード | 意味 |
|---|---|---|
| 1 | `gs.init(backend=gs.cpu)` | 計算に使う装置を決める（CPU / GPU） |
| 2 | `gs.Scene(sim_options=SimOptions(dt=0.02))` | 物理世界を作る。`dt` は1ステップで進む時間（0.02秒＝50Hz） |
| 3 | `scene.add_entity(...)` | 地面（Plane）やロボット（URDF）を置く |
| 4 | `scene.add_camera(...)` | 録画用のカメラを置く |
| 5 | `scene.build()` | 物理エンジン用にコンパイルする（初回は数十秒かかる） |
| 6 | `scene.step()` の繰り返し | 時間を `dt` ずつ進める |

- **URDF**: ロボットの形（リンク＝骨）と、つなぎ目（ジョイント＝関節）を書いたファイル。Go2 は Genesis に同梱（`urdf/go2/urdf/go2.urdf`）。
- 録画はカメラの `start_recording(save_to_filename=...)` から `stop_recording()` まで。その間は `scene.step()` のたびに自動で撮影される（Genesis 1.4.5）。

## 2. Go2 の体（12 関節）

脚が4本（FR＝右前、FL＝左前、RR＝右後、RL＝左後）。各脚に関節が3つある。

| 関節 | 動き | 立つときの角度 |
|---|---|---|
| hip（股） | 脚を横に開く | 0.0 rad |
| thigh（太もも） | 脚を前後に振る | 前 0.8 / 後 1.0 rad |
| calf（すね） | 膝を曲げる | -1.5 rad |

→ 行動（ロボットへの指令）は **12個の数字**。

## 3. PD 制御（関節をどうやって動かすか）

モーターに「この角度になれ」と指令すると、次の式でトルク（回す力）が決まる。

```
トルク = kp × (目標角 − 現在角) − kd × 角速度
```

- **kp（P＝比例）**: ずれが大きいほど強く戻す。ばねの硬さ。Go2 の学習コードでは 20。
- **kd（D＝微分）**: 速く動いているほどブレーキをかける。揺れを抑えるダンパー。0.5。
- 実験: 立つ姿勢を目標にして3秒動かすと
  - PD あり → 胴体の高さ 0.27 m で立ち続けた
  - PD なし → 0.08 m まで崩れた（脱力）
- **大事な点**: 強化学習の方策（AI）が出すのはトルクではなく **「目標の関節角度」**。それを PD 制御がトルクに直す。AI は細かい力加減を考えなくてよく、学習しやすくなる。

## 5. go2_env.py の中身（観測・行動・報酬）

**観測（AI への入力、45個の数字）** `_update_observation`
| 中身 | 個数 | 意味 |
|---|---|---|
| base_ang_vel | 3 | 胴体の回転の速さ |
| projected_gravity | 3 | 胴体から見た重力の向き＝どれだけ傾いているか |
| commands | 3 | 指令（前後速度・横速度・旋回速度） |
| dof_pos − default | 12 | 各関節の角度（立つ姿勢からのずれ） |
| dof_vel | 12 | 各関節の速さ |
| actions | 12 | 前回自分が出した行動 |

**行動（AI の出力、12個）** `step`: `目標角 = 行動 × 0.25 + 立つ姿勢` → PD 制御でトルクに。
- 実機の遅れを真似て、**1ステップ前の行動を実行**する（`simulate_action_latency`）。

**報酬（毎ステップの点数の合計）** 重みは `go2_train.py` の `reward_scales`
| 項目 | 重み | 何を評価するか |
|---|---|---|
| tracking_lin_vel | +1.0 | 指令の速度で前に進めているか（誤差が小さいほど 1 に近い） |
| tracking_ang_vel | +0.2 | 指令の旋回速度に合っているか |
| lin_vel_z | −1.0 | 上下に跳ねない |
| base_height | −50 | 胴体の高さを 0.3 m に保つ |
| action_rate | −0.005 | 行動を急に変えない（なめらかに） |
| similar_to_default | −0.1 | 立つ姿勢からかけ離れない |

**終了（リセット）**: 20秒たつ、または胴体が前後・左右に **10度** 以上傾いたら最初から。
→ 「傾いたら即終わり」なので、転ばないこと自体が長く報酬をもらう条件になっている。

**指令**: 公式設定は前進 0.5 m/s 固定（横・旋回は 0）。→ 今のモデルは「まっすぐ歩く」しかできない。

## 6. 報酬と PPO の仕組み（Go2 の場合）

**1 iteration の流れ**: 4096体 × 24ステップ動かす（約10万個の経験）→ PPO で方策を少し直す → これを101回。

**報酬の設計の考え方**
- 主役は「指令速度を追いかける」1項目だけ（`exp(−誤差²/0.25)` で 0〜1 点）。足の動かし方は教えていない → 歩き方は AI が自分で見つける。
- マイナスの項目（跳ねない・高さを保つ・なめらかに・変な姿勢にしない）はズル（報酬の抜け穴）を防ぐブレーキ。
- 10度傾くとエピソードが終わる＝転ぶとその後の点数がもらえない、という「見えない報酬」。
- 各重みに dt=0.02 を掛けるので、1000ステップ完走で最大約 20 点。学習後の 15.45 は満点の8割弱。

**PPO（rsl-rl）**
| 部品 | 内容 |
|---|---|
| Actor（方策） | 観測45 → 行動12。MLP 512-256-128。行動は正規分布で出す（学習中はばらつき＝探索、推論は平均だけ） |
| Critic（価値関数） | 観測45 → 「この先稼げそうな点数」1個。採点係 |
| アドバンテージ | （実際の点数＋その後の見込み）−（Critic の予想）。＋なら強め、−なら弱める |
| gamma=0.99 | 未来の点数の割引。約100ステップ（2秒）先まで考える |
| lam=0.95 | GAE。アドバンテージ計算を安定させる |
| clip_param=0.2 | 1回の更新で行動の確率を ±20% までしか変えない（覚えたことを壊さない）＝PPO の核心 |
| desired_kl=0.01 | 変化が大きすぎたら学習率を自動で下げる |
| 5 epoch × 4 minibatch | 集めた経験を何回使い回すか |

**なぜ 4096 並列か**: PPO は「今の方策で集めた経験」しか使えない（on-policy）。大量の経験を速く集めるため。

## 7. 2足立ち v1（2026-10-31, `go2_train.py --task stand -e go2-stand-v1`、500 iteration、Mac で約16分）

**変えたもの（報酬と終了条件だけ。PPO・ネットワーク・観測・行動は公式のまま）**
- 新しい報酬: upright（胴体の起き具合 `((1−g_x)/2)²`）+1.0、stand_height（0.30→0.50 m で 0→1）+1.0、front_feet_air（前足先の高さ 0→10 cm で 0→1）+0.5
- 残した報酬: 速度0の追従（その場にとどまる）+0.5 / 旋回 +0.2、lin_vel_z −0.2（公式 −1.0 から弱めた）、action_rate −0.01
- 外した報酬: base_height（0.3 m に固定しようとする）、similar_to_default（四つ足の姿勢に引き戻す）
- 終了条件: 前後・左右 10 度 → 「胴体の高さ < 0.15 m」または「横方向の重力成分 > 0.7（横に約45度）」
  - 直立付近（ピッチ ±90°）ではオイラー角が不安定（ジンバルロック）なので、重力ベクトルで判定する

**学習の経過**（1秒あたりの報酬。各項目の上限＝重み）
| iter | upright (1.0) | stand_height (1.0) | front_feet_air (0.5) | エピソード長 |
|---|---|---|---|---|
| 0 | 0.003 | 0.003 | 0.003 | 15 |
| 100 | 0.57 | 0.003 | 0.31 | 1001 |
| 300 | 0.78 | 0.004 | 0.43 | 992 |
| 499 | 0.91 | 0.17 | 0.47 | 983 |

- **100 iteration: 「お座り」の局所解。** 頭を約30度上げ、腰を落として前足を浮かせかけた姿勢で止まった。
  stand_height は 0.30 m を超えるまで 0 点で、四つ足の高さ（約 0.27〜0.30 m）からの手がかりがない → 楽に取れる upright だけを覚えた。
- **300〜500 iteration: 抜け出した。** upright がほぼ満点になり、前足が完全に浮き、stand_height が上がり始めた。
- 結果（ckpt 499）: 開始約0.5秒で後ろ足立ちになり、**10秒間転倒0回**、その場から 5 cm 以内。
- 残る課題: stand_height が 0.17（胴体の高さ約 0.33 m）。膝を曲げたまま立っている。
  → stand_height の範囲の下限を下げる（手がかりを早くから与える）、学習を延ばす、などで改善できそう。

## 8. ツルツルの床（2026-10-31）

**摩擦の仕組み（Genesis）**: 接触の摩擦 = `max(物体Aの摩擦 × 倍率, 物体Bの摩擦 × 倍率)`（`contact.py`）。
→ 床だけ滑りやすくしても、足の摩擦（既定 1.0）が使われるのでツルツルにならない。床と足の両方を下げる必要がある。

**v1（普通の床だけで学習）を滑る床で試す**（`eval_friction.py`、20秒あたりの転倒回数）
→ 摩擦 0.3 以下で立った直後に後ろ足が滑って転ぶ。学習した環境の外には弱い。

**ドメインランダム化**（`--task stand-slip`、v1 の 499 から 300 iteration ファインチューニング、約10分）
- 4096 体それぞれに、リセットのたびに摩擦 0.05〜1.0 をランダムに割り当てる。方策には摩擦を教えない（観測は同じ）。
- 実装: 床は 0.05 に固定し、ロボット側の倍率を環境ごとにランダム化 → 実際の摩擦 = ロボット側の値。
- `--resume` で学習済みの方策から続けて学習。最初はランダムな床で崩れる（エピソード長 45）が、50 iteration で 770、300 で 988 に回復。

| 摩擦 | v1 | slip（ランダム化） |
|---|---|---|
| 1.0 | 0 | 0 |
| 0.5 | 0 | 0 |
| 0.3 | 8 | 0 |
| 0.2 | 0 | 0 |
| 0.1 | 7 | 0 |
| 0.05 | 29 | 0 |

→ **「どんな床か分からないまま、どの床でも立てる」動き方を獲得**。実機に移すとき（実際の摩擦は分からない）に使う考え方と同じ。

## 9. 方策ネットワークの大きさと構成

```
観測45 → 全結合512 → ELU → 全結合256 → ELU → 全結合128 → ELU → 全結合12 → 行動の平均12
                                                         ＋ ばらつき std 12（観測に依存しない学習パラメータ）
```
- Actor: **189,336 パラメータ（約 740 KB）**。Critic も同じ形で出力1個（187,905）。動かすときは Actor だけ使う。
- モデルファイル 4.5 MB ＝ Actor + Critic + Adam の内部状態。
- 小さくて済む理由: 入力が画像ではなく 45 個の数字（体の感覚）で、反射的な制御だから。50Hz でもマイコン級の CPU で動く。

**ばらつき（std）の変化**: 学習前 1.0 → 四足歩行 0.60〜0.74 → 2足立ち 0.39〜0.59。
2足立ちで一番小さいのは **後ろ足の太もも（0.39, 0.41）** ＝ バランスの要の関節なので正確に動かすことを学んだ。

## 10. 2足歩行 v1（2026-10-31, `--task biped -e go2-biped-v1`、stand-slip の 798 から続けて学習）

**報酬**: 2足立ちの報酬（upright 1.0、stand_height 0.5、front_feet_air 0.5）＋ **世界座標**の前進速度の追従 1.5 ＋ 世界座標の旋回 0.3。指令は前進 0〜0.5 m/s（4秒ごとに引き直し）。歩き方（足の上げ方）は教えない。
- 落とし穴: 胴体が起きると胴体の x 軸は真上を向く → 公式の `base_lin_vel`（胴体座標）で速度を測ると「上に進め」になる。だから世界座標で測る。

**結果: 「立ったまま動かない」局所解**（1100 iteration、指令 0.4 m/s で10秒 → −0.03 m、転倒0）
- 前進の報酬は約 1.0（上限 1.5）。数字だけ見ると追従できていそうだったが、録画すると立ち止まっていた。
- 計算: 指令が 0〜0.5 m/s で sigma 0.25 だと、**立ち止まっても前進の報酬は満点の 75%（1.12/1.5）**。
  歩けば +0.38 だが、転ぶとその後の報酬（1秒あたり約3点）を全部失う → 立っているのが得、と学んだ。
- 学習は 1573 iteration で Mac のメモリ不足により停止（モデルは 1500 まで保存）。

**v2 の方針**: 立ち止まりを得にさせない。
| 設定 | 立ち止まりの点（満点1） |
|---|---|
| 指令 0〜0.5、sigma 0.25（v1） | 0.75 |
| sigma 0.05 | 0.40 |
| 指令 0.3〜0.5 | 0.53 |
| 両方 | 0.06 |
→ 両方＋ feet_air_time（後ろ足が 0.25 秒以上浮いてから着地で加点）を入れる。

| 実験 | 変更点 | 結果 | わかったこと |

### v2 の「前後ロッキング」局所解（重要）

- ピッチが **−82°〜−87° で 2.5 Hz 振動**。後ろ足2本は**一度も地面から浮かない**（接地率100%）。
- 世界座標の前進速度は **+0.25 と −0.25 m/s を交互**。平均 0 なのに、瞬間速度で追従報酬を稼いでいた。
- thigh 関節が 41〜44° で同じ周期に振動（これがロッキングの駆動源）。
- 報酬（1秒あたり）: upright 0.83 / front_feet_air 0.42 / tracking 0.17（満点1.5）。エピソード長 948/1001（ほぼ転倒しない）。

### 立ち姿勢の分析（「ガニ股で膝を伸ばし切り、関節限界に寄りかかっている」）

`go2-biped-v2` ckpt 1197 の実測（1.5〜5秒、1環境）:

| 関節 | 可動域 | 実際 | 方策の目標角 | 限界超えの割合 | 制御トルク |
|---|---|---|---|---|---|
| RL hip | ±60° | +60.1° | +98.4° | 100% | +13.4 Nm |
| RR hip | ±60° | −60.1° | −73.8° | 100% | −4.8 Nm |
| RL calf | −48〜−156° | −47.9° | −16.5° | 100% | +11.0 Nm |
| RR calf | 同上 | −47.9° | −18.9° | 100% | +10.1 Nm |
| thigh | −90〜200° | +42.5° | +84.2° | 0% | +14.6 Nm |

- 後ろ足の間隔 **0.83 m**（胴体幅 0.19 m の約4倍）。普通の犬は腰幅（Go2 なら 0.15〜0.2 m）。
- hip と calf は**毎ステップ限界を超える角度を指令**していて、関節ストッパーに寄りかかって立っている。制御で支えているのは thigh だけ。
- 原因: 報酬に「足を開く／膝を伸ばす」罰則がなく、広く伸ばすほど横安定＋高さ報酬が得。**関節限界が無料の支え**になっていた。
- 見た目: 1台のカメラの遠近で左右が非対称に見えるが、関節角の左右差は 0.3° 未満（hip は鏡映でほぼ完全一致）。

### v3 の方針（姿勢の矯正）

報酬を追加（`--task stand-natural`、`stand-slip` の 798 から 400 iter）:
- `hip_neutral` 1.0: `exp(-(hip/0.20 rad)²)`（hip を閉じる）
- `knee_bend` 0.5: calf を −1.40 rad（約−80°）に保つ
- `feet_width` 0.5: 後ろ足の左右位置を ±0.15 m に
- `stand_height` 1.0 → 0.3、範囲 0.28〜0.42 m（膝伸ばしへの圧力を下げる）
- upright 1.0 / front_feet_air 0.5 / 速度0追従 0.5 は維持

**予想されるトレードオフ**: 足を狭めると横バランスを能動制御で取る必要があり、最初は転倒が増える。
成功しても姿勢が崩れるなら、重みを上げて再学習する。

### v3 の結果（失敗：片脚だけ広げた非対称姿勢）

`go2-stand-natural` ckpt 1197（798 + 400 iter）の実測:

| 関節 | 実際 | 目標 | 限界超え | 制御トルク |
|---|---|---|---|---|
| RL hip | **+60.1°（限界）** | +73.5° | 100% | +4.7 Nm |
| RR hip | −1.5° | +3.0° | 0% | +1.6 Nm |
| RL calf | −81.4° | −78.1° | 0% | +1.2 Nm |
| RR calf | **−47.8°（限界）** | +19.6° | 100% | **+23.5 Nm（飽和）** |
| 足の間隔 | **0.48 m**（左右非対称） | — | — | — |
| 胴体 | pitch −69.7°、**roll +14.7°**、高さ 0.356 m | — | — | — |

- 左脚だけガニ股のまま限界に預け、右脚は正中に寄せる「片脚チート」。
- **原因1: 左右の平均で採点していた。** 片脚を広げても片脚を正常にすれば平均点が取れる。
- **原因2: roll（横傾き）に報酬がない。** 14.7° 傾いても終了条件（45°）に触れず、減点もない。
- 転倒は0（エピソード長 992/1001）なので「安定」ではあるが、見た目は犬ではなく、hip 限界依存も残る。

### v4 の方針（`--task stand-natural2`、v3 の 1197 から 400 iter）

- `posture_worst_leg`: hip / knee / feet_width を**左右の悪い方**の脚で採点（min）。片脚チートを封じる。
- `level` 0.5: `exp(-(g_y/0.10)²)` で横傾きを減点。
- 重み: hip_neutral 1.5、knee_bend 0.8、feet_width 0.8（v3 より強く）。
- 狙い: 左右対称・腰幅・膝を曲げた姿勢。ここが安定したら、歩行（EMA速度追従）へ進む。

### v4 の結果（失敗：左右非対称が残る）

`go2-stand-natural2` ckpt 1596（v3 の 1197 + 400 iter）:

- 良くなった点: 膝は左右とも **−82°** に曲がり、胴体高 **0.414 m**、ピッチ **−88°**（ほぼ直立）。
- 悪い点: 左 hip は **+60.2°（限界、トルク 20.8 Nm）** のまま、右 hip は −27.2°。足間隔 **0.56 m**、roll −6.4°。
- **min（悪い方の脚）で採点しても、左右対称にはならない。** 各脚を独立に評価するので「片脚を限界に預ける」解が残る。
- 原因: 片脚だけ閉じると転倒するため（下の手動テスト）。片脚チートは動力学上の安定解でもあった。

### 手動テスト: 股関節を閉じられるか（物理的な可否）

v4 の方策を動かしたまま、hip の目標角だけを 2 秒かけて強制変更:

| 操作 | 結果 |
|---|---|
| 左脚 hip だけ +60° → −27°（右脚の鏡像） | **4.5 秒で転倒**（roll +18°、base_z 0.24） |
| 両脚 hip を同時に ±20° へ | 転倒せず。実際の hip は +28°/−31°、足 ±0.27 m、胴体はやや沈む |
| 両脚 hip を同時に 0° へ | 6 秒転倒せず。足 ±0.20 m、base_z 0.34、roll +14°、pitch −54°（前傾） |

→ **左右同時に閉じるのは可能**。片脚だけ閉じると不安定なので、方策が片脚チートに落ちるのは自然。
ただし他の関節（thigh/calf）も狭い姿勢用に合わせないと、胴体が沈む・前傾する。

### v5 の方針（`--task stand-natural3`、v4 の 1596 から 800 iter）

- `hip_sym` 2.0: `exp(-((hip_L+hip_R)/0.10)²)` … 左右の hip を鏡像に
- `feet_sym` 1.0: `exp(-((y_L+y_R)/0.04)²)` … 左右の足の横位置を対称に
- `hip_neutral` 2.0（sigma 0.15）、`feet_width` 1.0（目標 ±0.15 m）、`knee_bend` 0.8、`level` 0.5 は維持
- 左右を同時に閉じる誘導を明示的に入れる。800 iteration（Mac で約27分）。

### v5 の結果（半分成功：左右対称になったが、もっと広がった）

`go2-stand-natural3` ckpt 2395（v4 の 1596 + 800 iter）:

| 指標 | v4 | v5 |
|---|---|---|
| 左右対称（hip_L + hip_R） | 33°（非対称） | **0.1°（対称）** |
| 後ろ足の間隔 | 0.56 m | **0.67 m（悪化）** |
| hip | 左 +60°（限界）/ 右 −27° | **左右とも ±60°（限界）** |
| 膝 (calf) | −82° | −76° |
| 胴体 | pitch −88°、roll −6.4° | pitch −87.6°、roll +2.7° |
| 前足の高さ | 0.22 m | 0.58 m（高く上げた） |

- 対称性の報酬（hip_sym / feet_sym）は効いた。**左右差はほぼゼロ**。
- しかし hip は両方とも限界に張り付いたまま。**ガウス報酬 `exp(-(x/sigma)²)` は限界（60°）で値も勾配もほぼ 0** なので、閉じる方向の学習信号が消えていた。
- さらに、片脚チートが消えたぶん「両脚で踏ん張る」方向に最適化が進み、間隔はむしろ広がった。

### v6 の方針（`--task stand-natural5`、v2 の 1197 から 800 iter）

- **二次罰則**に変更（遠くても勾配が残る）:
  - `hip_penalty` −5.0 × mean(hip²) … 60° で −5.5/秒
  - `feet_width_penalty` −40.0 × mean(relu(y−0.15)²) … 0.335 m で −1.4/秒
  - `knee_penalty` −5.0 × mean(relu(calf+1.20)²)
- hip_sym / feet_sym / level / knee_bend は維持。
- 出発点は v2（左右対称・ガニ股）。限界に張り付いた v5 より、行動が極端でないぶん抜け出しやすいと判断。

**この一連の失敗から言えること（レポート用）**: 報酬の形（ガウス vs 線形 vs 二次）は「学習できるか」を左右する。目標から遠い初期状態では、ガウス報酬は値も勾配も 0 になり、方策は動かない。関節限界は「無料の支え」として最適化に悪用される。

### v6 の結果（失敗：罰則を逃れるために「しゃがむ」）

`go2-stand-natural5`（v2 の 1197 から、二次罰則つきで学習）:

- **254 iteration で方策が崩壊**。直立報酬 0.047（ほぼ横たわり）、エピソード長は 982 のまま（終了条件を満たさない）。
- 実際の姿勢（ckpt 1400）: **hip ±1.8°（閉じた）、calf −85/−79°（曲げた）、足間隔 0.265 m** だが、**pitch −28.6°（前傾）、前足 0.119 m（接地寸前）、高さ 0.318 m** ＝ うつ伏せ気味のしゃがみ。
- 狙った「足を閉じる」は達成したが、「立つ」を捨てた。**罰則 −5.5/秒が直立報酬 1.0/秒を上回り、しゃがめば罰則を回避できる**構造だった。
- 終了条件が「高さ < 0.15 m」「横重力 > 0.7」だけなので、**しゃがみは終了しない** ＝ 無限に罰則を避けられる。

**教訓**: 罰則を強くするだけでは、タスクそのものを放棄する別の局所解に落ちる。姿勢報酬は「直立しているときだけ」与えるゲートが必要。

### v7 の方針（`--task stand-natural6`、v6 の 1400 から 600 iter）

- `posture_gate`: hip/knee/feet/symmetry/level の報酬に **直立度 `((1-g_x)/2)²` を掛ける**。しゃがむと姿勢点がもらえない。
- upright 5.0（最優先）、front_feet_air 1.0
- 罰則は弱める: hip −2.0、feet −20、knee −3.0
- 出発点は v6 の「脚は閉じているがしゃがんでいる」モデル。そこから直立させる狙い。

### v7 の結果（成功：自然な立ち姿勢）

`go2-stand-natural6` ckpt 1999（v6 の 1400 + 600 iter）:

| 指標 | v2（元） | v7（成功） |
|---|---|---|
| hip（左右） | ±60.1°（限界） | **+2.0° / −1.8°** |
| calf（膝） | −47.9°（限界） | **−87.5° / −84.8°（曲げた）** |
| 足の間隔 | 0.83 m | **0.30 m**（腰幅に近い） |
| 胴体の高さ | 0.35 m | **0.413 m** |
| pitch / roll | −87° / ±0° | **−77.5° / +1.0°** |
| 関節限界への依存 | 100% | **0%** |
| 10秒間の転倒 | 0 | **0** |

- 見た目: 後ろ足を腰幅に置き、膝を曲げ、前足を上げた「おねだり」姿勢（`videos/go2-stand-natural6_ckpt1999.mp4`）。
- 効いた工夫: **姿勢報酬を直立度でゲート**し、強い直立報酬（5.0）。さらに v6 の「脚は閉じているがしゃがんでいる」モデルを初期値に使った。
- **失敗を初期値として再利用**できたのが大きい（v6 で脚を閉じる動き自体は学習済みだった）。

### v8 の方針（2足歩行、`--task biped3`、v7 の 1999 から 600 iter）

- 立ち止まり報酬（速度0追従）を外す。
- **移動平均した世界座標の速度**で追従を評価（`vel_filter_tau` 0.5 秒）。前後ロッキングで瞬間速度を稼ぐ抜け道を封じる。
- `tracking_lin_vel_ema` 3.0、`tracking_ang_vel_ema` 0.5、`feet_air_time` 1.0（目標 0.15 秒）。
- 指令は前進 0.2〜0.4 m/s のみ（横・旋回は 0）。
- 姿勢報酬（直立 5.0、hip/膝/足幅/対称/level）は維持。歩くときも姿勢が崩れないようにする。

### v8 の結果（失敗：移動平均でも立ち止まり）

`go2-biped-v8`（v7 の 1999 から 224 iter 時点で中断）:

- `tracking_lin_vel_ema` 0.52/3.0、`feet_air_time` 0、エピソード長 973、うつ伏せ転倒 0。
- 移動平均でロッキングは封じたが、**立ち止まりでも追従報酬の 17% が入る**（cmd 0.3、sigma 0.05）。
- 姿勢報酬の合計が約 9/秒あり、歩行で得られる上積み（最大 +2.8/秒）より大きい。**リスクを取って歩く理由がない。**

### v9 の方針（`--task biped4`、v7 の 1999 から 800 iter）

- `progress` 6.0: `clip(v_ema_x / cmd_x, 0, 1)` … **立ち止まりは 0 点**、指令どおりで 1 点。線形で勾配が残る。
- `tracking_lin_vel_ema` は横方向のズレ用に 1.0 へ弱める。
- 姿勢報酬を控えめに（hip 0.5、膝 0.3、足幅 0.3、対称 0.5/0.3、level 0.3、前足 0.5）。直立 5.0 は維持。
- `air_time_target` 0.10 秒（短い一歩でも拾う）。
- 狙い: 立ち止まり 7.7/秒 vs 歩行 14.5/秒（約1.9倍）にし、歩く方を明確に得にする。

### v9 の結果（失敗：片脚支持の壁）

`go2-biped-v9`（v7 の 1999 から 223 iter 時点で中断）:

- `progress` 0.62/6.0（前進は約 0.03 m/s）、`feet_air_time` 0、エピソード長 813（転倒が増えた）。
- 立ち止まりの取り分を 0 にしても、**片脚で立って足を振り出す**という探索が成功しない。
- 物理的な難しさ: 後ろ足2本は点接地。片足を上げると支持多角形が「点」になり、COM を支持足の真上に置き続ける必要がある。これは歩行の中でも最も難しい部分。

### v10 の方針（ホッピング、`--task biped5`、v7 の 1999 から 800 iter）

- 片脚バランスを避け、**両足同時に跳ぶ**（ウサギ跳び）方向へ。
- `flight` 4.0: 後ろ足2本が同時に接地から離れている時間。
- `progress` 6.0（移動平均の前進達成率）、`feet_air_time` 1.0。
- 姿勢報酬は v9 と同じ控えめ設定、直立 5.0 は維持。
- ホップは「離陸→滞空（支持不要）→着地」で、片脚支持より動力学が単純。

### v10 の結果（半分成功：その場ホップ、しかも後ろ向き）

`go2-biped-v10` ckpt 2798（v7 の 1999 から 800 iter）:

- 学習中: `flight` 3.2/4.0（滞空約80%）、`progress` 2.2/6.0、直立 3.3/5.0、エピソード長 932。
- 推論（指令 0.4 m/s、10秒）: **x = −1.07 m（後ろ向きに 0.11 m/s）**、転倒0。
- 両足同時のホップは覚えたが、**「跳ぶ」だけで flight 報酬が入る**ため、前進と結びつかず、後ろ向きホップに収束。
- 「片脚支持」よりホップの方が学習しやすいことは確認できた（滞空80%まで到達）。

### v11 の方針（`--task biped6`、v10 の 2798 から 800 iter）

- `flight` を**前進速度でゲート**: `flight × clip(v_ema_x / 0.15, 0, 1)`。垂直・後方ホップでは滞空報酬ゼロ。
- `progress` 8.0 に増強、`backward` −3.0（後退罰則）を追加。
- 指令 0.3〜0.5 m/s。

### v11 の結果（失敗：往復ホップを「前進」と誤認）

`go2-biped-v11` ckpt 3000 の軌道（指令 0.4 m/s、10秒）:

- 後ろ足は**ほぼ常に浮いている**（接地率0）。base_z 0.30〜0.41 で推移 → 連続ホップ。
- しかし x は **+1.39 m → −0.26 m → 再び前進** を約4秒周期で往復。ピッチも −80°〜−25° と大きく振れる。
- つまり「その場で激しく前後にはねている」だけで、**0.5秒の移動平均（EMA）では往復が打ち消えない**。progress 2.4/8 は前進ではなく往復の一部を拾っていた。

**教訓**: 速度の移動平均では、周期の長い往復を除去できない。**リセットからの累積移動距離**で評価する必要がある。

### v12 の方針（`--task biped7`、v7 の 1999 から 800 iter）

- `progress_cum` 8.0: `(x − x_reset) / 経過時間` を指令速度で割った達成率。往復ホップは 0 点。
- `flight` も**累積平均速度でゲート**（`flight_gate_avg`）。
- `backward` −2.0 は維持。瞬間の `progress` は 0（使わない）。

### v12 の結果（失敗：累積評価にすると、ただ立つ）

`go2-biped-v12`（v7 の 1999 から 223 iter 時点で中断）:

- `progress_cum` 0.003/8.0、`flight` 0.001、`backward` −0.07、直立 4.5/5.0、転倒なし。
- 往復ホップは消えたが、**前進もしない**（その場立ち）。累積評価は「往復」を正しく 0 にしたが、ホップ自体をやめさせた。
- 前進ホップには「跳ぶ」と「前へ進む」を同時に満たす必要があり、現状の報酬ではその組み合わせを発見できない。

### v13 の方針（その場足踏み、`--task step`、v7 の 1999 から 400 iter）

歩行の最も難しい部分（片足支持）を単独で練習する。
- `single_support` 3.0: 後ろ足のうち**ちょうど1本だけ接地**（片足で立つ）
- `swing` 2.0: 上げている足の高さ（踏み出し）
- `feet_air_time` 1.0、指令は 0（その場）
- 姿勢報酬（直立 5.0 など）は v7 のまま維持
- これができるようになったら、前進指令と `progress` を足して歩行（v14）へ。

### v13 の結果（半分成功：片足で10秒立ち続ける）

`go2-step-v13` ckpt 2398:

- 学習中: `single_support` 2.55/3.0（85%の時間が片足支持）、`swing` 1.72/2.0、`feet_air_time` 0。
- 推論: **片足で10秒間静止**（接地足は固定、上げた足は高さ 0.93 m）。転倒0、x −0.22 m。
- 片足バランスという難しい primitive は獲得したが、**足を上げっぱなしで踏み替えない**（報酬が「片足支持＋高い振り上げ」だけで、切り替えを要求していない）。
- `feet_air_time` が 0 なのは、上げた足が一度も着地しないため。

### v14 の方針（`--task step2`、v13 の 2398 から 400 iter）

- `support_switch` 2.0: 支持足が入れ替わった瞬間に加点。
- `support_hold_penalty` −2.0: 同じ足で 0.6 秒以上立ち続けたら罰則。
- `single_support` 1.0、`swing` 0.5 に弱め、`feet_air_time` 2.0（着地を評価）。
- 狙い: 片足立ちのまま固まらず、左右に踏み替える「その場足踏み」。

### v15 の結果（失敗：両足接地に逃げる）

`go2-step-v15`（踏み替え検出のバグを直した版、v13 の 2398 から 188 iter 時点で中断）:

- `support_switch` 0.036/2.0（踏み替えほぼ無し）、`support_hold_penalty` −0.65、`single_support` 0.33、`swing` 0.06。
- **両足接地（double support）に逃げた。** 同じ足で立ち続ける罰則はあるが、両足で立てば罰則がかからない。
- 報酬設計の穴: 「片足立ち」と「両足立ち」のどちらも、踏み替えずに安定できる。踏み替えだけが疎な報酬なので学習されない。

### v16 の方針（`--task step4`、v13 の 2398 から 400 iter）

- `double_support_penalty` −2.0: 両足で立つこと自体に罰則。
- `support_switch` 5.0 に増強、`support_hold_penalty` −3.0（0.4秒で発動）。
- `swing_time` 1.0: 足が浮いている時間を連続で評価（着地しないと 0 になる疎な報酬を補う）。
- これで「片足で立ち続ける」も「両足で立つ」も損になり、踏み替えだけが得になる設計。

### v16 の結果（失敗：片足立ちのまま踏み替えられない）

`go2-step-v16`（v13 の 2398 から 189 iter 時点で中断）:

- `single_support` 0.86/2.0、`support_switch` 0.12/5.0（約42秒に1回）、`support_hold_penalty` −1.27、`double_support_penalty` −0.65、`swing_time` 0.30。
- 片足で立ったまま、たまに長く保持する。**踏み替え（支持足の交代）が起きない。**
- 踏み替えには「上げていた足を着地 → 支持足を上げる」の2段階が必要で、片足立ちの方策から探索で抜けにくい。
- これ以上の報酬調整は、歩行そのものより「報酬ハックとの戦い」になってきた。

### ここまでの結論（2足歩行）

- 2足立ち（自然な姿勢）: **成功**（v7）。
- 2足歩行: ホップ（v10）と片足バランス（v13）までは到達したが、前進歩行・踏み替えは未達。
- 失敗の共通構造: (1) 立ち止まりが安全で高得点、(2) 片脚支持が動力学的に難しい、(3) 報酬の抜け道（ロッキング、往復ホップ、両足立ち、片足立ち）が常に存在し、そのたびに報酬を設計し直す必要があった。
- レポートでは「報酬設計だけでは〇〇まで、××は未達」「各失敗で何を学んだか」を時系列で書ける。
